## О проекте

<!-- 3–5 предложений, как для человека, который не читал ТЗ. Не вставляйте сюда историю обучения — только суть задачи. -->

Задача: спроектировать процесс договорной работы для компании N (средний бизнес, ~150 сотрудников, 3–5 договоров в неделю). Проблема исходного процесса: согласование по почте, сроки не контролируются, оригиналы теряются. Целевое решение — 1С:Документооборот с типовыми механизмами согласования, утверждения и подписания.

## Ключевые решения

<!-- 3–5 пунктов, каждый — «проблема → решение → почему так». Это самый важный раздел: показывает мышление аналитика, а не владение рисовалкой. -->

- **Проблема:** согласование затягивалось на 10+ дней из-за параллельного обсуждения по почте. **Решение:** разделены согласование (обсуждение, несколько итераций) и утверждение (одна точка принятия решения) — в 1С:ДО это разные процессы с разными жизненными циклами.
- **Проблема:** срыв срока не фиксируется. **Решение:** типовые сроки этапов согласования с контролем просроченных заданий.
- **Проблема:** ручной перенос статусов. **Решение:** автоматическая смена статуса документа по завершении этапа маршрута.
